# Knowledge Base Workflow Reference

This document maps the investment research knowledge base (`Knowledge-Base/`) workflow, showing where each file is stored, what data it contains, and how the **kb-discovery** and **kb-intake** agents interact with it.

## Quick Reference: KB File Index

| Location | Purpose | Data Type | Owner | Access |
|---|---|---|---|---|
| `Knowledge-Base/index.md` | Main wiki index + recently-updated table | Front matter index | Regenerated by `kb_pages.py` | Read-only |
| `Knowledge-Base/portfolio/index.md` | Portfolio section index | Front matter index | Regenerated by `kb_pages.py` | Read-only |
| `Knowledge-Base/portfolio/holdings.md` | **Generated** holdings table (ticker, company, group, weight, value, qty, yield, confidence) | Portfolio data synced from classification JSON | `kb-sync-portfolio` skill | Read (by discovery); regenerated by sync |

| `Knowledge-Base/logs/decision-log.md` | **Append-only** record of all buy/sell/trim/add/reject decisions | Rows: date, tickers, action, verdict, note | Append-only via `kb_pages.append_log()` | Read; Append (via `kb-update-thesis` skill) |
| `Knowledge-Base/logs/research-log.md` | **Append-only** record of what was researched, when, from what sources | Rows: date, tickers, action, sources, note | Append-only via `kb_pages.append_log()` | Read; Append (via `kb-intake-document` skill) |
| `Knowledge-Base/logs/update-log.md` | **Append-only** changelog for the research wiki (separate from `CHANGELOG.md`) | Rows: date, change_type, pages_affected, summary | Append-only via `kb_pages.append_log()` | Read; Append (by all writing skills) |

## Agent Workflows

### KB-Discovery Agent Workflow

**Purpose:** Read-only search to gather context before research or as a standalone lookup.

**Entry Points:**
- "What do we know about TICKER?"
- "Find my thesis on TICKER"
- "Search for X" (sector, macro, earnings topic)
- Pre-research context before another task

**Workflow:**

```
User Request
    ↓
kb-discovery agent (haiku, Bash + Read)
    ↓
[1] Run kb_search.py with filters (--query, --ticker, --type, --tag, --status)
    ↓
[2] Read matched file paths
    ↓
[3] Extract:
    - Page title, type, status, summary from front matter
    - For stocks/TICKER.md: current status, Updated Thesis excerpt, Decision History recent rows
    - For holdings.md: ticker metadata, group, weight, yield, link to full thesis
    - For research notes: source date, key findings excerpt
    ↓
[4] Return Context Report:
    - Matched pages (paths, relevance)
    - Current thesis status + latest decision
    - Related sources + research dates
    - Explicit "not in KB" if empty
```

**Files Accessed (Read-Only):**
- `portfolio/holdings.md` — ticker metadata
- `portfolio/portfolio-overview.md` — allocation context
- `stocks/TICKER.md` — thesis and decision history
- `earnings/earnings-notes/` — earnings research
- `market-research/*-notes/` — sector/macro/sentiment context
- `sources/*/` — ingested documents
- `logs/decision-log.md` — decision history
- `logs/research-log.md` — research history

### KB-Intake Agent Workflow

**Purpose:** The only writer to the wiki. Ingests documents, creates/updates theses, manages status changes, syncs portfolio data.

**Entry Points:**
- "Add this document to the knowledge base" (file provided)
- "Ingest this PDF/report"
- "Create a thesis for TICKER"
- "Update the thesis for TICKER (with new information)"
- "Mark TICKER as active/watchlist/closed/rejected"
- "Sync the knowledge base with my portfolio"

**Core Workflow:**

```
User Request (ingest | create | update | status | sync)
    ↓
[1] RUN KB-SEARCH FIRST (mandatory)
    - Search for existing page/research/decision on the topic
    - If creating a thesis: check stocks/TICKER.md doesn't exist
    - If updating: Read existing page and extract current thesis
    ↓
[2] Route by request type:
    
    ┌─ INGEST DOCUMENT ────────────────────────┐
    │ kb-intake-document skill                 │
    │ ├─ Convert file via markitdown          │
    │ ├─ File under sources/2026/<date>-<slug>.md
    │ ├─ Optional: scaffold companion note     │
    │ │  under earnings/ or market-research/  │
    │ ├─ Update sources/index.md               │
    │ └─ Append research-log.md + update-log.md│
    └─────────────────────────────────────────┘
    
    ┌─ CREATE THESIS (NEW TICKER) ─────────────┐
    │ kb-update-thesis skill (create subcommand)│
    │ ├─ Instantiate from template             │
    │ ├─ Pre-fill from classification JSON     │
    │ ├─ Update stocks/index.md                │
    │ ├─ Create theses/<status>/index entry    │
    │ └─ Wait for agent to fill prose          │
    └─────────────────────────────────────────┘
    
    ┌─ UPDATE THESIS (EXISTING TICKER) ────────┐
    │ [A] kb_search verify page exists         │
    │ [B] Read stocks/TICKER.md                │
    │ [C] Extract current Original Thesis +    │
    │     Decision History + Updated Thesis    │
    │ [D] Agent (SONNET) compares new info to  │
    │     old assumptions → verdict            │
    │ [E] Edit ONLY:                          │
    │     - Updated Thesis (new section)      │
    │     - Analysis sections (financial,      │
    │       technical, sentiment, etc.)        │
    │     - Monitoring Checklist                │
    │     - Open Questions                     │
    │     - Decision History (new row via      │
    │       append_log.py, never edit old)     │
    │ [F] kb-update-thesis validate --path     │
    │ [G] append_log.py decision --action      │
    │ [H] Update stocks/index.md               │
    │ [I] Maybe update theses/<status>/        │
    │     if status changed                    │
    │ [J] Append update-log.md + decision-log.md│
    └─────────────────────────────────────────┘
    
    ┌─ STATUS CHANGE (active→closed, etc) ────┐
    │ kb-update-thesis set-status subcommand   │
    │ ├─ Update front-matter status field      │
    │ ├─ Update Status block (Last Updated)    │
    │ ├─ Regenerate theses/<old_status> +     │
    │    theses/<new_status> views             │
    │ ├─ append_log.py decision with verdict   │
    │ └─ Append update-log.md                  │
    └─────────────────────────────────────────┘
    
    ┌─ SYNC PORTFOLIO ─────────────────────────┐
    │ kb-sync-portfolio skill                  │
    │ ├─ Read classification JSON              │
    │ ├─ Regenerate holdings.md                │
    │ │  (ticker, name, group, weight, value,  │
    │ │   qty, yield, confidence, link to      │
    │ │   stocks/TICKER.md if exists)          │
    │ ├─ Regenerate portfolio-overview.md      │
    │ │  (group allocation vs policy,          │
    │ │   currency split, needs-review)        │
    │ ├─ Update portfolio/index.md             │
    │ └─ Append update-log.md                  │
    └─────────────────────────────────────────┘
    
    ↓
[3] FOR THESIS WORK: Run kb-update-thesis validate
    ↓
[4] Report Wiki Update Summary:
    - Pages created/updated (repo-relative paths)
    - For stocks/TICKER.md: thesis verdict + what changed
    - Log entries appended (which logs)
    - Monitoring next steps or gaps
```

**Files Written:**

| Request Type | Files Modified | Write Mode |
|---|---|---|
| **Ingest document** | `sources/2026/<date>-<slug>.md` | Write new |
| | `sources/index.md` | Update front-matter index table |
| | `<dest_folder>/index.md` (if scaffold note) | Update front-matter index table |
| | `logs/research-log.md` | Append row |
| | `logs/update-log.md` | Append row |
| **Create thesis** | `stocks/TICKER.md` | Write new |
| | `stocks/index.md` | Update front-matter index table |
| | `theses/<status>/index.md` | Update front-matter index table |
| | `logs/update-log.md` | Append row |
| **Update thesis** | `stocks/TICKER.md` | Edit (never Original Thesis or old Decision History rows) |
| | `logs/decision-log.md` | Append new row |
| | `logs/update-log.md` | Append row |
| **Status change** | `stocks/TICKER.md` | Edit front-matter + Status block |
| | `theses/<old_status>/index.md` | Update to remove page |
| | `theses/<new_status>/index.md` | Update to add page |
| | `logs/decision-log.md` | Append row |
| | `logs/update-log.md` | Append row |
| **Sync portfolio** | `portfolio/holdings.md` | Regenerate (write new) |
| | `portfolio/portfolio-overview.md` | Regenerate (write new) |
| | `portfolio/index.md` | Update front-matter index table |

    │  {title: "Apple Inc", status: "active", tickers: [AAPL],

    │
    ├─ Extract recent Decision History:
    │  Last: 2026-07-10 | Action: Add | Verdict: stronger | 
    │        "Q3 margins beat expectations"
    │

    │  AAPL | Apple | Technology | 4.2% | $42K | 100 sh | 0.44% | Confidence: HIGH
    │
    └─ Return Context Report:

    --page stocks/NVDA.md --action "Create new thesis"

## Immutability Rules (KB-Intake Agent Constraints)

**Never edit or delete:**
- `Original Thesis` section in `stocks/TICKER.md` — once written, it is locked to preserve the initial investment thesis for comparison with later research
- Any existing row in `logs/decision-log.md`, `logs/research-log.md`, `logs/update-log.md` — logs are append-only for auditability
- `ref/` classifier YAML files — those belong to the classification workflow

**Only append to (never edit existing rows):**
- `logs/decision-log.md` — new rows via `append_log.py decision --action ... --verdict ...`
- `logs/research-log.md` — new rows via `append_log.py research --action ... --sources ...`
- `logs/update-log.md` — new rows via `append_log.py update --page ... --action ...`
- `Decision History` table in `stocks/TICKER.md` — new rows only, via `append_log.py decision`

**May edit:**
- `Updated Thesis` section in `stocks/TICKER.md` — reflects current conviction as research accumulates
- All analysis sections (`Financial Analysis`, `Valuation`, `Technical Analysis`, `Market Sentiment`, `Options Activity`, `Insider Activity`, `Earnings and Catalysts`, `Dividend Analysis`, `Portfolio Fit`, `Bull Case`, `Bear Case`, `Key Risks`) — updated with new findings
- `Open Questions` section — adds or resolves questions as research progresses
- `Monitoring Checklist` — adjusted as thesis evolves
- Front-matter `updated` date and `status` field — managed by skill scripts on status change or agent edit

**No standalone decision-record or portfolio-review pages:** sell/trim
decisions and periodic portfolio reviews are recorded entirely within the
relevant `stocks/TICKER.md` page(s) — `Decision`/`status` field changes,
an appended `Decision History` row, and an `Updated Thesis` edit
explaining the reasoning. There is no separate `portfolio/decisions/` or
`portfolio/review-*.md` file type in this workflow.

## Skill Scripts Quick Reference

### kb-search
```bash
python .claude/skills/kb-search/scripts/kb_search.py \
  --query <text> \
  --ticker <TICKER> \
  --type <stock-page|earnings-note|...> \
  --tag <tag> \
  --status <active|draft|...> \
  --limit <N> \
  --json
# Exit 0 on no matches; output: path, title, type, tickers, status, updated, summary
```

### kb-sync-portfolio
```bash
python .claude/skills/kb-sync-portfolio/scripts/sync_portfolio_pages.py \
  --classification <path-to-json> \
  --check  # dry-run, no write
# Regenerates: portfolio/holdings.md, portfolio/portfolio-overview.md, indexes, logs
```

### kb-intake-document
```bash
python .claude/skills/kb-intake-document/scripts/intake_document.py \
  --input <file.pdf|file.docx|...> \
  --title <optional> \
  --tickers <AAPL,NVDA> \
  --doc-type <optional> \
  --dest-folder <earnings|macro|sector|sentiment|options|sources-only> \
  --source-date <YYYY-MM-DD>
# Writes: sources/2026/<date>-<slug>.md + optional companion note, updates indexes and logs
```

### kb-update-thesis
```bash
# Create new thesis
python .claude/skills/kb-update-thesis/scripts/thesis_page.py create \
  --ticker <AAPL> \
  --status <active|watchlist|closed|rejected|research> \
  --company-name <optional>

# Validate existing page
python .claude/skills/kb-update-thesis/scripts/thesis_page.py validate \
  --path <stocks/AAPL.md>

# Change status
python .claude/skills/kb-update-thesis/scripts/thesis_page.py set-status \
  --ticker <AAPL> \
  --status <active|watchlist|closed|rejected|research>

# Append log row
python .claude/skills/kb-update-thesis/scripts/append_log.py \
  --log <decision|research|update> \
  --date <YYYY-MM-DD> \
  --tickers <AAPL,NVDA> \
  --action <describe action> \
  --verdict <new|stronger|weaker|unchanged|broken> \  # decision only
  --sources <source refs> \  # research only
  --page <path> \  # update only
  --note <optional detail>
```

```bash
python .claude/skills/kb-search/scripts/validate_kb.py
# Reports: front-matter errors, missing required fields, broken links, index inconsistencies
```

### Regenerate all indexes
```bash
python .claude/skills/kb-search/scripts/validate_kb.py --fix-indexes
# Updates: all index.md files (except hand-curated: theses/index.md, logs/index.md, taxonomy/index.md)
```

### Test a sync without writing
