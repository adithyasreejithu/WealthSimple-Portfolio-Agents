# Research Wiki (Knowledge Base)

This document describes the investment research knowledge base implemented
under `Knowledge-Base/`, phase 1 of
`docs/plans/goals/stock_decision_support_system.md`. For the full
implementation plan, see
`docs/plans/implementation/stock_decision_support_phase1.md`.

## Two zones in `Knowledge-Base/`

`Knowledge-Base/` predates this work and already held the approved portfolio
classification YAMLs. Rather than create a second, confusingly-similarly-
named directory (`knowledge-base/` and `Knowledge-Base/` are the same path
on Windows' case-insensitive filesystem), the research wiki extends the
existing directory as a second zone:

1. **Classifier reference** — `ref/*_v1_1.yaml`, `README.md`,
   `CHANGELOG.md`. Loaded directly by `src/portfolio_classifier.py` via
   `src/config.py`'s `KNOWLEDGE_BASE_FOLDER`/`PORTFOLIO_GROUPING_FOLDER`.
   Unchanged by this work; wiki agents never write here.
2. **Research wiki** — everything else: `portfolio/`, `stocks/`, `theses/`,
   `earnings/`, `dividends/`, `market-research/`, `sources/`, `taxonomy/`,
   `templates/`, `logs/`, and the main `index.md`.

## Layout

```text
Knowledge-Base/
├── ref/                    # classifier zone — unchanged, never edited by KB agents
├── index.md                 # main wiki index + recently-updated table
├── portfolio/                # overview, holdings (generated), allocation policy, risk log
├── stocks/                  # one canonical page per ticker: stocks/TICKER.md
├── theses/                  # status views (active/watchlist/closed/rejected) over stocks/
├── earnings/earnings-notes/
├── dividends/
├── market-research/{sector,macro,sentiment,options}-notes/
├── sources/<year>/          # markitdown conversions of ingested documents
├── taxonomy/                 # links ref/*.yaml as source of truth + decision-framework.yml
├── templates/                # page templates + front-matter-spec.md
└── logs/                     # decision-log.md, research-log.md, update-log.md
```

Canonical stock pages never move: `stocks/TICKER.md` carries a `status`
field, and `theses/<status>/index.md` are regenerated *views* over it, so
links into a stock page stay stable even as its status changes.

## Front matter

Every wiki page (everything except `ref/`, `README.md`, `CHANGELOG.md`)
starts with YAML front matter — the substrate `kb-search` searches. The full
field list, allowed `type`/`status` combinations, and an example are in
`Knowledge-Base/templates/front-matter-spec.md`. `src/kb_pages.py` is the
single implementation: parsing, validation, index-table rendering, and
append-only log formatting.

## Page ownership

| Page(s) | Owner | Notes |
|---|---|---|
| `portfolio/holdings.md`, `portfolio/portfolio-overview.md` | `kb-sync-portfolio` skill (generated) | Never hand-edited; re-run the skill instead. |
| `stocks/TICKER.md` | `kb-update-thesis` skill (structure) + `kb-intake` agent (prose) | Original Thesis and Decision History are append-only/immutable. |
| `sources/<year>/*.md` | `kb-intake-document` skill | Faithful markitdown conversion; never summarized. |
| Notes under `earnings/`, `dividends/`, `market-research/` | `kb-intake-document` (scaffold) + `kb-intake` agent (content) | |
| `taxonomy/decision-framework.yml` | Hand-curated | Decision/confidence/time-horizon/verdict enums only — group taxonomy stays in `ref/`. |
| Every `index.md` | Regenerated by `kb_pages.rebuild_index`/`rebuild_thesis_views`/`rebuild_main_index` | `theses/index.md`, `logs/index.md`, `taxonomy/index.md` are hand-curated navigation with no marker table and are excluded from auto-rebuild. |
| `logs/*.md` | Append-only, via `src/kb_pages.py` helpers | Never edited or deleted. |

## Skills and agents

| Skill | Purpose |
|---|---|
| `kb-search` | Front-matter-aware search (`kb_search.py`) and wiki validation/index-rebuild (`validate_kb.py`). |
| `kb-sync-portfolio` | Regenerates the two generated portfolio pages from `exports/portfolio-classification/portfolio-classification.json`. |
| `kb-intake-document` | Converts an external document to markdown via `markitdown`, files it under `sources/`, optionally scaffolds a companion note. |
| `kb-update-thesis` | Deterministic edges of the thesis lifecycle: create/validate/set-status, plus append-only log helpers. |

| Agent | Role | Tools |
|---|---|---|
| `kb-discovery` | Read-only search and context reporting. | `Bash`, `Read` |
| `kb-intake` | The only agent that writes to the wiki: document intake, thesis create/update, status changes, portfolio sync. | `Bash`, `Read`, `Edit`, `Write` |

Full per-agent documentation: `docs/agents/kb-discovery/` and
`docs/agents/kb-intake/`.

## Changelog split

`Knowledge-Base/CHANGELOG.md` continues to track only classifier YAML
versions. The research wiki's own change history is
`Knowledge-Base/logs/update-log.md`, appended to by every skill that mutates
a wiki page.

## No new CLI commands

Every wiki workflow is a skill script invoked directly
(`python .claude/skills/kb-*/scripts/*.py ...`), following the same pattern
as `reconcile-holdings-report`. No `src/app.py` subcommand was added, so
`docs/reference/cli.md` is unaffected by this work.
