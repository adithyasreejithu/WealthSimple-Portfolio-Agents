# Front-Matter Specification

Every markdown page in the research wiki (everything under `Knowledge-Base/`
except `ref/`, `README.md`, and `CHANGELOG.md`) starts with a YAML front-matter
block. This metadata is how the `kb-search` skill and the `kb-discovery` agent
locate pages — a page without valid front matter is invisible to discovery.
`src/kb_pages.py` is the single implementation of this spec;
`validate_kb.py` (in the `kb-search` skill) enforces it.

## Fields

| Field | Required | Meaning / allowed values |
|---|---|---|
| `title` | yes | Human-readable page title. |
| `type` | yes | One of: `stock-page`, `research-note`, `earnings-note`, `dividend-note`, `sector-note`, `macro-note`, `sentiment-note`, `options-note`, `source-document`, `portfolio-page`, `decision-record`, `taxonomy`, `template`, `log`, `index`. |
| `tickers` | yes (may be `[]`) | Uppercase pipeline symbols the page is about, e.g. `AAPL`, `ENB`, `XEQT`. |
| `tags` | yes (may be `[]`) | Kebab-case topic tags, e.g. `dividends`, `valuation`, `cad-exposure`. |
| `status` | yes | Depends on `type` — see below. |
| `created` | yes | `YYYY-MM-DD`, never changed after creation. |
| `updated` | yes | `YYYY-MM-DD`, bumped on every substantive edit. |
| `summary` | yes | One sentence; rendered into index tables, so keep it short and specific. |
| `related` | no | List of page-relative markdown paths to related wiki pages. |
| `sources` | no | List of `{title, ref, date}`; `ref` is a URL or a path to a `sources/` page. |
| `generated_at` | no | ISO timestamp; only on pages regenerated by skills (`status: generated`). |

## Status values by type

| Type | Allowed `status` |
|---|---|
| `stock-page` | `active`, `watchlist`, `closed`, `rejected`, `research` |
| note types + `source-document` + `decision-record` | `draft`, `final`, `archived` |
| `portfolio-page` | `generated`, `draft`, `final`, `archived` |
| `taxonomy`, `template` | `draft`, `final` |
| `log` | `final` |
| `index` | `generated`, `final` |

A `stock-page` status is its portfolio lifecycle state and drives the
`theses/<status>/index.md` views. `generated` marks pages rebuilt by skills —
never edit those by hand.

## Example

```yaml
---
title: "Apple Inc. (AAPL) — Stock Page"
type: stock-page
tickers: [AAPL]
tags: [quality, technology, usd]
status: active
created: 2026-07-11
updated: 2026-07-11
summary: "Quality compounder; hold; monitoring services growth and buyback pace."
related:
  - ../portfolio/holdings.md
sources:
  - {title: "Q3 FY2026 10-Q", ref: "../sources/2026/2026-08-01-aapl-10q.md", date: 2026-08-01}
---
```

## Index tables

Every folder's `index.md` contains a table between `<!-- kb-index:begin -->`
and `<!-- kb-index:end -->` markers, regenerated from page front matter by
`src/kb_pages.py` helpers (`validate_kb.py --fix-indexes` rebuilds them all).
Row format:

```
| [Title](page.md) | type | tickers | status | updated | summary |
```
