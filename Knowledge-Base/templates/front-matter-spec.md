# Front-Matter Specification

Every markdown page in the research wiki (everything under `Knowledge-Base/`
except `ref/`, `README.md`, and `CHANGELOG.md`) starts with a YAML front-matter
block. This metadata is how the `kb-search` skill locates pages — a page
without valid front matter is invisible to search.
`src/kb_pages.py` is the single implementation of this spec;
`validate_kb.py` (in the `kb-search` skill) enforces it.

## Fields

| Field | Required | Meaning / allowed values |
|---|---|---|
| `title` | yes | Human-readable page title. |
| `type` | yes | One of: `stock-page`, `research-note`, `earnings-note`, `dividend-note`, `sector-note`, `macro-note`, `sentiment-note`, `competitor-note`, `options-note`, `source-document`, `portfolio-page`, `decision-record`, `taxonomy`, `template`, `log`, `index`. |
| `tickers` | yes (may be `[]`) | Uppercase pipeline symbols the page is about, e.g. `AAPL`, `ENB`, `XEQT`. |
| `tags` | yes (may be `[]`) | Kebab-case topic tags, e.g. `dividends`, `valuation`, `cad-exposure`. |
| `status` | yes | Depends on `type` — see below. |
| `created` | yes | `YYYY-MM-DD`, never changed after creation. |
| `updated` | yes | `YYYY-MM-DD`, bumped on every substantive edit. |
| `summary` | yes | One sentence; rendered into index tables, so keep it short and specific. |
| `related` | no | List of page-relative markdown paths to related wiki pages. Now secondary to derived tag-based lookup — `kb-search` recall runs off `tickers:`/`tags:`, not this field. |
| `sources` | no | List of `{title, ref, date}`; `ref` is a URL or a path to a `sources/` page. May carry a `confidence` tier — one of `verified`, `vetted`, `scraped`, `social` (decision #15). |
| `section_updated` | no | Mapping of `<section-key>: YYYY-MM-DD`, recording when the writer agent last rewrote each gated section of a `stock-page`. Populated only for sections actually rewritten; a missing key falls back to the top-level `updated:` date. Consumed by the staleness gate (`kb-staleness-gate`) to decide which sections are due (decision #16). |
| `generated_at` | no | ISO timestamp; only on pages regenerated by skills (`status: generated`). |

## Status values by type

| Type | Allowed `status` |
|---|---|
| `stock-page` | `active`, `watchlist`, `closed`, `rejected`, `research` |
| note types + `source-document` + `decision-record` | `draft`, `final`, `archived` |
| `portfolio-page` | `generated`, `draft`, `final`, `archived` |
| `taxonomy`, `template` | `draft`, `final` |
| `log` | `final` |
| `index` | `generated`, `final` |

A `stock-page` status is its portfolio lifecycle state and drives the
`theses/<status>/index.md` views. `generated` marks pages rebuilt by skills —
never edit those by hand.

## Example

```yaml
---
title: "Apple Inc. (AAPL) — Stock Page"
type: stock-page
tickers: [AAPL]
tags: [quality, technology, usd]
status: active
created: 2026-07-11
updated: 2026-07-11
summary: "Quality compounder; hold; monitoring services growth and buyback pace."
related:
  - ../portfolio/holdings.md
sources:
  - {title: "Q3 FY2026 10-Q", ref: "../sources/2026/2026-08-01-aapl-10q.md", date: 2026-08-01}
---
```

## Section staleness (`section_updated`)

`stock-page` sections go stale at different rates, so freshness is tracked
per-section rather than per-page. The writer agent stamps
`section_updated[<key>] = <today>` for each gated section it rewrites; the
`kb-staleness-gate` skill reads that map to decide which sections are due
(decision #16). Section keys and their cadence tiers:

| Tier | Cadence | Section keys |
|---|---|---|
| Weekly (market-driven) | 7 days | `status`, `market_sentiment`, `options_activity` |
| Monthly (fundamentals/judgment) | 30 days | `valuation_analysis`, `company_overview`, `bull_case`, `bear_case`, `key_risks`, `open_questions`, `monitoring_checklist`, `portfolio_fit`, `updated_thesis`, `analyst_view`, `insider_activity` |

`technical_analysis` joins the weekly tier once the technical-analysis phase
ships (a placeholder section today, so it is not gated yet). DB-backed
sections (Earnings and Catalysts, Dividend Analysis, Financial Analysis) and
event-driven sections (Original Thesis, Decision History, Sources) are never
gated — see decision #16. A page written before this field existed simply has
no keys; every key falls back to top-level `updated:`, so no migration is
needed.

## Index tables

Every folder's `index.md` contains a table between `<!-- kb-index:begin -->`
and `<!-- kb-index:end -->` markers, regenerated from page front matter by
`src/kb_pages.py` helpers (`validate_kb.py --fix-indexes` rebuilds them all).
Row format:

```
| [Title](page.md) | type | tickers | status | updated | summary |
```
